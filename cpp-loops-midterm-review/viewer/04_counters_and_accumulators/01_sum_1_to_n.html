Adding Up 1 to N - the Accumulator and its Shortcut

Beginner accumulators + the closed formula n * (n + 1) / 2 256 lines 11 kb
Reading tip. Every grey note below is a collapsible explanation. Click its header to read it, or press C to hide every comment at once so the program logic stands on its own.

WHAT THIS PROGRAM TEACHES

  • The classic ACCUMULATOR: sum is created as 0 BEFORE the loop and
  • WHY the accumulator must start at 0 rather than 1, in plain words.
  • The arithmetic-operator family + - * / % and what each is for.
  • The 10-second formula n * (n + 1) / 2, and a loop that checks it.
  • Why n * (n + 1) / 2 always divides exactly, for every whole n.

EXPECTED OUTPUT

=== Adding up 1 to 10 with a loop ===
The loop total is 55
=== The 10-second formula n * (n + 1) / 2 ===
For n = 10 the formula gives 55
=== Checking that the two agree ===
55 == 55 - the loop matches the formula.

IMPORTANT SYNTAX

int sum = 0;               -> an accumulator starts at zero
sum = sum + i;             -> fold the new value into the running total
sum += i;                  -> exactly the same thing, written shorter
n * (n + 1) / 2            -> multiply, then add 1, then divide by 2
sum == formula             -> "are these two the same?" (a question)

STEP-BY-STEP EXPLANATION

  1. int n = 10; is the upper limit, given a name so the loop and the
  2. formula can both use it and be changed in one place.
  3. int sum = 0; is the accumulator, created BEFORE the loop. This is
  4. the single most important line in the program.
  5. The loop adds i into sum for every i from 1 to n, then i++ moves on.
  6. After the loop sum holds the finished answer, 55.
  7. n * (n + 1) / 2 computes the same answer with no loop at all: the
  8. maths has a shortcut that saves you writing the loop on an exam.
  9. == compares the two answers so the agreement is proven, not assumed.

THE COMMON TRAP IN THIS FILE

Writing `int sum;` with no starting value, or `int sum = 1;`.
With no value at all the program is illegal in C++ - the compiler
refuses with "sum was not initialised" - because there would be no
answer to add to on the first pass. With 1 it compiles perfectly and
prints 56. Accumulators must be given a value BEFORE the loop, and
that value must be the identity for the operator being used:
adding      -> 0
multiplying  -> 1

Exam questions

What value must an adding accumulator start at, and why?
Answer: 0, because 0 is the identity for + so the first number passes through unchanged
What does this loop produce for n = 10?
Answer: 55, from 1 + 2 + 3 + ... + 10
Why are the brackets needed in n * (n + 1) / 2?
Answer: without them division happens before multiplication, giving 100 instead of 55
Why does n * (n + 1) / 2 never lose a fraction?
Answer: one of n and n+1 is always even, so the product divides by 2 exactly
What is the difference between sum == formula and sum = formula?
Answer: == compares them, while = overwrites sum and loses the loop answer

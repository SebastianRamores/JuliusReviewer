Counting Positives, Negatives and Zeros in a List

Beginner three counters + if / else if / else, and reading an array 233 lines 11 kb
Reading tip. Every grey note below is a collapsible explanation. Click its header to read it, or press C to hide every comment at once so the program logic stands on its own.

WHAT THIS PROGRAM TEACHES

  • How to store a fixed list of numbers in an ARRAY and walk through it
  • Using THREE separate counters at the same time, one for each category.
  • if / else if / else: testing several possibilities in order, and
  • > 0, < 0 and "neither", which together cover every whole number.

EXPECTED OUTPUT

=== Counting positives, negatives and zeros ===
The list holds 10 numbers.
Positives: 5
Negatives: 4
Zeros: 1
=== Check ===
5 + 4 + 1 = 10, which matches the length of the list.

IMPORTANT SYNTAX

int numbers[] = {5, -3, 0, ...}; -> an ARRAY: a fixed row of int valuesnumbers[i] -> the value stored at position i
if (numbers[i] > 0) { } else if (numbers[i] < 0) { } else { }-> only ONE of these three branches runs

STEP-BY-STEP EXPLANATION

  1. The array holds the ten fixed values. An array is a row of boxes, all
  2. of the same type, and every box has a NUMBER called an index.
  3. Indexing starts at 0, so the values live at 0 to 9. numbers[0] is
  4. 5 and numbers[9] is 4. Position 10 would be past the end.
  5. All three counters are set to 0 BEFORE the loop, since each starts by
  6. finding nothing.
  7. The loop visits every box once. For each value exactly one of the
  8. three branches runs and raises its counter by 1.
  9. The final check adds the three counters and finds 10, which is the
  10. length of the list - proof that every value was counted exactly once.
  11. ============================================================

REPORTING

================================================================

THE COMMON TRAP IN THIS FILE

Writing the loop as `for (int i = 1; i <= howMany; i++)`. Starting
at 1 SKIPS the first value and reading numbers[10] runs off the end
of the row entirely. The loop must be `i = 0; i < howMany;`. Array
indexes run 0 to howMany - 1, which is why the test uses `<` and not
`<=`. The check at the bottom is what makes the mistake visible: the
counts would add up to 9 instead of 10.

Exam questions

How many positives, negatives and zeros are in the list?
Answer: 5 positives, 4 negatives and 1 zero
Which indexes does the array actually use?
Answer: 0 to 9, because indexing starts at 0 for ten values
Why does the else branch not need a condition?
Answer: a value that is neither above 0 nor below 0 can only be 0
What is wrong with for (int i = 1; i <= howMany; i++) here?
Answer: it skips box 0 and reads past the end at numbers[10]
What would the total check print if one value had been missed?
Answer: the sum would be 9 rather than 10, showing a value was uncounted

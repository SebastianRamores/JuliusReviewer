Finding the Average - and Why Integer Division Loses It

Beginner accumulators + counters + the double type and type conversion 267 lines 12 kb
Reading tip. Every grey note below is a collapsible explanation. Click its header to read it, or press C to hide every comment at once so the program logic stands on its own.

WHAT THIS PROGRAM TEACHES

  • An average is found in three steps: add everything up, count how many
  • Why sum / count with two ints throws the fraction away - INTEGER
  • The trap nobody expects: putting double on the LEFT of the division
  • How to force a real division by converting one side with a cast.

EXPECTED OUTPUT

=== Step 1: sum and count ===
Sum of the 10 numbers is 23
Count is 10
=== Step 2: dividing two whole numbers ===
23 / 10 as int division gives 2
=== Step 3: a double on the left does NOT help ===
Declaring the answer as double still gives 2
=== Step 4: convert one side BEFORE dividing ===
23 / 10 as a double gives 2.3
That is the correct average.

IMPORTANT SYNTAX

int count = 0; -> a counter, for how many there aresum / count -> INTEGER division: the fraction is discarded

STEP-BY-STEP EXPLANATION

  1. One loop does both jobs: it adds each value into sum and raises
  2. count by 1, so the two always describe the same set of numbers.
  3. int wrong = sum / count; gives 2, because both sides are ints and
  4. the division throws away the 0.3.
  5. double stillWrong = sum / count; ALSO gives 2. The division is
  6. carried out in ints first, and only the finished 2 is turned into a
  7. double afterwards.
  8. double average = (double) sum / count; converts sum to a double
  9. BEFORE the division happens, so the answer keeps its fraction: 2.3.
  10. The mean of the list is therefore 2.3, not 2.
  11. ============================================================

THE DATA - THE SAME TEN FIXED NUMBERS AS FILE 06

An ARRAY is a fixed row of values, all of one type, each in its own
numbered box. `int numbers[]` - `int` is the element type, `[]` after

INDEXING STARTS AT 0, so these ten values live at boxes 0 to 9.

STEP 1 - ADD EVERYTHING UP AND COUNT AT THE SAME TIME

================================================================

THE COMMON TRAP IN THIS FILE

Stopping at Step 2 and printing `wrong`, which is 2 instead of 2.3.
It is a perfectly reasonable-looking line of code and it compiles
with no warning whatsoever. The habit that prevents it is to decide
the type of the ANSWER before writing the division: if the answer
might have a fraction anywhere in it, make sure a `double` is
involved in the division, not merely in the variable that receives
it. A good exam habit is to ask "could this ever be a half?" before
dividing anything.

Exam questions

What are the final values of sum and count?
Answer: 23 and 10
What does 23 / 10 give when both sides are ints, and why?
Answer: 2, because integer division discards the .3 instead of rounding
Why does double stillWrong = sum / count; still give 2?
Answer: the division is carried out in ints first; only the finished 2 is converted afterwards
What is the correct average of the list, and how is it forced?
Answer: 2.3, by casting one side: (double) sum / count
Why can the running total in this loop go DOWN?
Answer: sum is fed negative values as well as positive ones, such as -3 and -15

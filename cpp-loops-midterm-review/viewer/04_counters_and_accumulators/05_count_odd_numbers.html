Counting How Many Odd Numbers Are in 1 to 50

Beginner counters, the odd-number test, and a loop-free shortcut 271 lines 11 kb
Reading tip. Every grey note below is a collapsible explanation. Click its header to read it, or press C to hide every comment at once so the program logic stands on its own.

WHAT THIS PROGRAM TEACHES

  • The same COUNTER pattern applied to ODD numbers instead of even.
  • Doing the counting with a while loop, where the counter must be declared
  • The shortcut: the number of odd numbers in 1 to n is (n + 1) / 2, so a

EXPECTED OUTPUT

=== Method 1: a while loop that tests every number ===
Loop body ran 50 times.
Odd numbers found: 25
=== Method 2: a while loop that steps by 2 ===
Loop body ran 25 times.
Odd numbers found: 25
=== Method 3: no loop at all, just the arithmetic ===
(50 + 1) / 2 = 25, and that is how many odd numbers there are.
=== Cross-check ===
25 odd + 25 even = 50, which is the whole list, so nothing is missing.

IMPORTANT SYNTAX

int count = 0;         -> a counter, created before the loop
while (i <= 50) { }    -> test at the top, so 0 passes is possible
i++;                   -> add 1 to i by hand, there being no header slot
i += 2;                -> add 2 to i, to visit odd numbers only
count++;               -> one more odd number found
(n + 1) / 2            -> integer division, which rounds DOWN

STEP-BY-STEP EXPLANATION

  1. int i = 1; sits ABOVE the loop, because a while header has room for
  2. the test only - unlike a for header, it cannot declare anything.
  3. The test i <= 50 is asked before every pass; on the 51st, i is 51
  4. and the loop ends.
  5. count++ fires only when i % 2 == 1, so count rises 25 times.
  6. Method 2 steps by 2 from 1, so every pass is a hit and the test can be
  7. deleted - 25 passes instead of 50.
  8. Method 3 uses arithmetic instead of looping; the cross-check proves the
  9. two counts add back up to the length of the list.

THE COMMON TRAP IN THIS FILE

Forgetting `i++;` at the bottom of the body. A for loop has it in
the header where it is hard to lose; a while loop puts it in the
body, where it is easy to leave out. The result is an infinite loop
printing the same line until you kill it - i stays 1, so `i <= 50`
stays true. Method 2 hangs the same way without its `i += 2`.

Exam questions

How many odd numbers are there between 1 and 50?
Answer: 25
Why must i be declared above the while loop?
Answer: a while header holds only the condition, so there is nowhere inside it to declare anything
What does integer division do with the 51 / 2 in Method 3?
Answer: it truncates, giving 25 and discarding the .5
What would happen if i++; were deleted from Method 1?
Answer: an infinite loop, because i would stay 1 and the test would stay true
What would count be if count++ were replaced by count = count + i?
Answer: the sum of the odd numbers, 625, not the number of them

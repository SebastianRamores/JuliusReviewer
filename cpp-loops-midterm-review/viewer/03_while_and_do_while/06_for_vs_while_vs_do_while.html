WHAT THIS PROGRAM TEACHES

  • The SAME job - adding up 1 to 10 - written correctly three times.
  • All three programs must produce the same answer, and the program
  • Where each loop type tests its condition, and what that decides.
  • How to pick the right loop for a new question on an exam.

EXPECTED OUTPUT

=== Version 1: for loop ===
Sum using for = 55
=== Version 2: while loop ===
Sum using while = 55
=== Version 3: do...while loop ===
Sum using do...while = 55
=== Agreement check ===
All three methods produce the same answer: 55

IMPORTANT SYNTAX

for (int i = 1; i <= 10; i++) { sumFor += i; }^ start, then test, then update - all in one header
while (w <= 10) { sumWhile += w; w++; }^ test first, so the body may run zero times
do { sumDo += d; d++; } while (d <= 10);^ test last, so the body always runs once
sumFor += i; -> add i into the running total and store it back&& -> "AND": true only when BOTH sides are true

STEP-BY-STEP EXPLANATION

  1. Version 1 packs the start value, the test and the update into the for
  2. header, so the loop counter i lives and dies with the loop.
  3. Version 2 does the same work with the counter declared beforehand, and
  4. w++ written at the bottom of the body instead of in a header.
  5. Version 3 uses the same counter and the same test, but the test comes
  6. after the body. With these starting values the result is identical.
  7. The three totals are compared with ==, joined by &&. Because both
  8. comparisons hold, the program reports that all three agree.
  9. Note what would NOT agree: a do...while whose counter starts already
  10. beyond the limit, because it would add one number too many.
  11. ============================================================

THE COMMON TRAP IN THIS FILE

Writing `if (sumFor = sumWhile)` with one equals sign. That does not
compare anything: it throws sumWhile's value into sumFor and then
treats the result as true whenever sumWhile is not zero. The program
would print "they agree" even when they did not. Compare with `==`,
assign with `=`, and never mix them up.

Exam questions

What answer do all three versions produce, and why?
Answer: 55, because 1 + 2 + ... + 10 = 55 in every case
Which of the three types tests its condition after the body?
Answer: do...while, so it can never run fewer than one time
Why can sumFor be declared inside the loop header instead of above it?
Answer: the for header creates it, which keeps it out of the rest of main
What would the do...while version give if d started at 20?
Answer: 20, not 0, because its body runs once before any test is made
What is wrong with if (sumFor = sumWhile)?
Answer: = assigns instead of comparing, so no real test is performed

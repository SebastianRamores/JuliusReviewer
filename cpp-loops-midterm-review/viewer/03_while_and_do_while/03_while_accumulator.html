WHAT THIS PROGRAM TEACHES

  • The ACCUMULATOR pattern: one variable that carries a running answer
  • Why an accumulator MUST be initialised before the loop - add with 0
  • How sum = sum + i; is read in two steps, right to left.
  • Printing the running value each pass so the pattern becomes visible.

IMPORTANT SYNTAX

int sum = 0;            -> start a running total at zero
int product = 1;        -> start a running product at one
sum = sum + i;          -> add i into the total and store it back
sum += i;               -> exactly the same thing, written shorter
product = product * j;  -> multiply j into the product
product *= j;           -> exactly the same thing, written shorter

STEP-BY-STEP EXPLANATION

  1. int sum = 0; creates the accumulator BEFORE the loop. Created inside
  2. the loop it would be thrown away and rebuilt on every pass, so nothing
  3. would ever be carried forward.
  4. int i = 1; creates the loop counter, also before the loop.
  5. while (i <= 10) asks "is i at most 10?". TRUE runs the body, FALSE
  6. leaves the loop and the program continues below the closing brace.
  7. sum = sum + i; is the heart of the pattern. Read it in two steps:
  8. work out the total of the old sum plus i, then store that back in sum.
  9. The print shows the total after each pass, so you can watch it grow.
  10. i++ moves the counter on. Deleting it would loop for ever.
  11. Part 2 repeats the pattern with * instead of +, which is exactly
  12. why its accumulator starts at 1 instead of 0.

THE COMMON TRAP IN THIS FILE

Writing `product = 0;` instead of `product = 1;`. The loop runs
happily, prints every line, and gives the answer 0 - and on row 1
the reason is invisible, because 0 * 1 really is 0. Ask instead
"what is the identity for this operator?": 0 for + and -, 1 for *.
A wrongly initialised accumulator gives a wrong answer silently.
The second trap is putting the accumulator INSIDE the loop. C++
would allow `while (...) { int sum = 0; sum = sum + i; }`, but sum
would be destroyed and rebuilt every pass, so it would never grow.

Exam questions

What are the running totals after adding 4 and after adding 5?
Answer: 10 and 15
What final value does sum hold, and why?
Answer: 55, the total of every whole number from 1 to 10
Why must an adding accumulator start at 0?
Answer: 0 is the identity for +, so 0 + first number passes it through unchanged
Why must a multiplying accumulator start at 1 and not 0?
Answer: anything multiplied by 0 is 0, so starting at 0 would give 0 for ever
Where must the accumulator be declared, and why?
Answer: before the loop, so it keeps its value from one pass to the next
